# Prompt 微创新 · 规则手册（v0.3 新增）

> 来源：v1-v5 五轮迭代 + 9 个 test case 实测，全部规则都是**踩过坑才定下的硬约束**。
> 任何调用本 skill 的 agent / 用户都应遵守。违反规则 = 知道会出错但故意出错。

---

## 一、写作规则（写新 prompt 时必守）

### R1 · 微创新至少 2 个非重叠变换

- 从 SCAMPER-LP 7 维中选 **至少 2 个**，且这 2 个**不能是同维度**（如不能同时选 2 个 Substitute）
- 推荐组合（不重叠 + 互补）：
  | 组合 | 适用 |
  |---|---|
  | Substitute + Modify | 换情绪对象 + 放大细节 → 稳健 |
  | Substitute + Reverse | 换钩子 + 反转方向 → 大胆 |
  | Combine + Adapt | 杂交套路 + 跨域改造 → 破圈 |
  | Eliminate + Modify | 删冗余 + 放大隐藏宝藏 → 精细 |
- ❌ 反模式：只 Substitute（=换皮）、选 2 个 Substitute（=重复）

### R2 · 必须保留至少 1 个原版钩子关键词

- 原版 hook 关键词至少保留 **1 个等价词**到新 prompt
- hook 关键词表：`鼓励 / 点赞 / 祝福 / 加油 / 请 / 能不能 / 求`
- v3 → v4 测试发现：把"求鼓励"改成"求领养"会丢钩子 → skill 正确判定失败
- 例外：如果是有意"换钩子"，应在 prompt.md 里显式标注 `hook_change: intentional`

### R3 · 关键口播必须含"具体数字 / 具体物件 / 具体人名"

- "只能他说"测试要求：关键口播句含**只有这个角色能说**的细节
- 具体细节 3 类（至少各 1 个）：
  - **数字**：年/岁/次/个/天/月/趟
  - **物件**：工牌/拉链/胶带/手帕/铁丝/铜铃/挂件
  - **身份**：姓名/年龄/职业/工龄/家乡
- ❌ 反例："能不能给我们一点鼓励"（任何角色都能说）
- ✅ 正例："这铃铛是我 17 岁当兵那年给它挂的，这一挂就是 1095 天"

### R4 · 戏根保留（来自芦苇编剧模型 2）

- 识别原 prompt 的**奠基性动作**（如"领回来/收养/等待/退休/回来/团圆/送别"）
- 微创新后必须保留至少 **1 个奠基性动作**（可用等价词）
- 等价词表见 `scripts/innovate.py` 的 `_get_alts()` 函数

### R5 · 困境—突围弧线必须显式

- 微创新 prompt 必须同时含**困境信号词 + 突围动作词**
- 困境词：`求 / 孤独 / 无助 / 可怜 / 残 / 病 / 贫困 / 失 / 难 / 苦 / 痛 / 唯一 / 最后 / 冷 / 饿 / 留守 / 流浪`
- 突围词：`去 / 做 / 走 / 找 / 回来 / 领 / 收养 / 送 / 帮 / 鼓励 / 支持 / 守 / 等 / 撑 / 坚持`
- v4 测试发现：P4 母婴题材微创新缺这两类词 → skill 正确判定失败

### R6 · 护城河细节密度 3 类至少各 1 个

| 维度 | 含义 | 至少 |
|---|---|---|
| 感官 (sensory) | 视觉/触觉/听觉/嗅觉的具体描写 | 1 个 |
| 节奏 (rhythm) | 镜头/声音的时间结构 | 1 个 |
| 文化 (cultural) | 地域/年代/职业/民俗的具体符号 | 1 个 |

详细模式库见 `scripts/innovate.py` 的 `SENSORY_PATTERNS / RHYTHM_PATTERNS / CULTURAL_PATTERNS`
- v4 测试发现：SENSORY/CULTURAL 模式库需覆盖全题材（手艺传承/教育/科研/市井/公益），否则会误判

## 二、自检规则（6 项必须全过）

| # | 检查 | 来源 | 通过条件 |
|---|---|---|---|
| ① | 原作核心钩子还在？ | prompt-micro-innovate v0.1 | 至少 1 个原 hook 关键词或其等价词在新 prompt 中 |
| ② | 给创作者/观众更多决策空间？ | prompt-micro-innovate v0.1 | 新 prompt 长度 ≥ 原 prompt 长度 × 0.9 |
| ③ | 情感共鸣能跨过半衰期？ | prompt-micro-innovate v0.1 | Jaccard 相似度 < 70% |
| ④ | 戏根保留？ | luwei-screenwriting 模型 2 | 至少 1 个奠基动作保留 |
| ⑤ | 困境—突围弧线保留？ | luwei-screenwriting 模型 3 | 困境词 + 突围词 同时出现 |
| ⑥ | 关键台词过"只能他说"？ | luwei-screenwriting 启发式 #7 | 关键口播含具体数字/物件/身份 |

**任一项不通过 → 视为不合格微创新，必须回滚重做**

## 三、相似度阈值

| 对比维度 | 阈值 | 说明 |
|---|---|---|
| 与原始 prompt | **< 70%** | 高于 70% 视为换皮抄袭 |
| 与历史所有 prompt | **< 70%** | 高于 70% 视为撞历史爆款 |
| 撞避坑清单 | **0 个** | 任一命中即视为重蹈覆辙 |

- 70% 是初始值，可调（v3 测试发现：71% 的微创新也会被拦，skill 正确执行）
- 相似度算法：当前用 Jaccard 2-gram，TODO 接入真 embedding 相似度

## 四、输出规则

### R7 · 4 类输出文件结构（不可缺）

每日产出目录 `outputs/YYYY-MM-DD/` 必须包含：

| 文件 | 内容 | 必须 |
|---|---|---|
| `prompt.md` | 选中 prompt（YAML + 原版/改了什么/新版/6 项自检/JSON/备选章节） | ✅ |
| `insights.md` | 候选打分表 + 题材分布 + skill 自检 JSON + 待接入说明 | ✅ |
| `index.html` | 三栏对比（选中卡片：原版/改了什么/新版）+ 备选档折叠 | ✅ |
| `0X_alt_*.md` | N 个备选档（每条含评分/原版/淘汰原因） | ✅ 至少 1 个 |

### R8 · YAML frontmatter 必带字段

```yaml
date: 2026-08-07            # ISO 日期
seq: 001                    # 当日序号
skill: prompt-micro-innovate
skill_version: v0.3          # 必带版本号
mode: degraded_run | normal # 必须标模式
original_id: P2            # 原始 prompt 的 ID
original_source: manual_feed | daily_reverse_skill
original_title: ...        # 原始标题
core_hooks: [...]          # 识别的钩子（数组）
transforms: [...]          # SCAMPER-LP 维度名（数组）
similarity_to_original: 18.11%
similarity_to_history: 0% | N/A
detail_score: {sensory: 5, rhythm: 7, cultural: 3}
three_questions: {...}
luwei_checks: {...}
passed: true | false
note: ...                  # 可选备注
```

### R9 · 备选档命名格式

- 选中 ID 的备选按分数降序排列
- 文件名：`0X_alt_<ID>.md`（X = 2~9）
- 例：`02_alt_P5.md` `03_alt_P4.md`

### R10 · 三栏对比（index.html 核心）

选中卡片展开 `.compare-section`，3 列：
- 左：📜 原版 prompt（完整）
- 中：🔧 改了什么（SCAMPER-LP 变换表 + 6 项自检）
- 右：✨ 新版 prompt（完整）

备选档用 `<details>` 折叠，只展示原版 + "未做微创新"提示。

## 五、流程规则

### R11 · 候选池 < 3 → 触发人工介入

- 候选池大小 < 3 → 走"人工 review"分支
- = 3 是边界值，不触发
- > 3 正常走自动化

### R12 · 重试上限 3 次

- 每次微创新自检不通过 → 重新选变换重写
- 最多重试 **3 次**
- 3 次都不通过 → 触发人工 review（按 spec "重试 3 次仍不达标"）
- skill 不强制计数，由调用方负责

### R13 · 降级模式必须明示

当以下任一缺失时，输出文件 YAML 里 `mode: degraded_run`：
- 无每日逆向 skill → 候选池仅来自手动喂入
- 无分析 skill → 无历史数据可参考
- 无 embedding 相似度 → 用 Jaccard 近似
- 无微创新 skill 历史库 → 6 项自检的避坑清单为空

**降级模式 ≠ 错误**，是已知能力缺失，文件依然要落盘 + 标注。

### R14 · 仅命中触发条件才 review

按 spec 6 条触发条件：
1. 候选池 < 3
2. 重试 3 次仍不达标
3. 微创新 skill 调用失败/超时
4. 分析 skill 读不到历史数据
5. 输出文件写入失败
6. 用户手动标注"作废"

任一命中 → 第 8 步写入前暂停 + 展示草稿预览给用户 → 通过才落盘。

## 六、测试规则（写新测试时该检查什么）

v4-v5 测试发现的常见 bug 类别，写新测试时**主动覆盖**：

| Bug 类别 | 怎么测 | v4/v5 案例 |
|---|---|---|
| 断言写错（期望与实际不符） | 跑前先手算 expected 值 | TC-1（sim>90 期望错） |
| Python f-string walrus 限制 | 不能在 f-string 里用 `:=` | TC-8 |
| 同名不同 rank 文件冲突 | 每次跑前清空目录 | v5 备选档重复 |
| 模式库覆盖不全 | 新加一个全新题材测试 | TC-2（P4 母婴） |
| 文化/地域细节识别 | 加对应领域关键词到模式库 | TC-2/V5-01（手艺传承） |
| 重试路径断言 | 跑完整 3 次迭代 | TC-5 |

## 七、反模式（不要这样做）

来自 game-methodology M00 反模式 + prompt 场景特化：

| 反模式 | 后果 | 替代方案 |
|---|---|---|
| ❌ 只换皮（只 Substitute） | 平台判同质化 100% | 至少 2 维 + 1 个深层变换 |
| ❌ 靠堆料掩饰坏食材 | 一眼 AI 套话 | 写真实生活细节（鞋底泥/工牌磨痕） |
| ❌ 过度删减 | 失去原 prompt 张力 | Eliminate 必须过"原作核心乐趣还在？" |
| ❌ 改"换"认不出原作灵魂 | 失去迁移的爆款基因 | 保留至少 1 个奠基动作 |
| ❌ AI 套话代替生活细节 | 没有护城河 | 护城河密度 sensory ≥ 1, cultural ≥ 1 |
| ❌ 撞避坑清单 | 重蹈覆辙 | 选变换前看避坑清单 |
| ❌ 微创新后不验证就提交 | 平台重判风险 | 必须过 6 项自检 |

## 九、v0.4 增量规则

### R7.5 · 全员微创新（备选也要做）

- 每日产出时，**所有候选**（不只是选中的）都必须产出一版微创新 prompt
- 理由：用户切换备选时无需重跑，且方便横向对比"同原版不同创新方向"
- 文件体现：
  - 备选档 `0X_alt_*.md` 必须含 `new_prompt` + `transforms` 字段
  - index.html 备选卡片的 `<details>` 默认折叠，点开展示三栏对比（与选中卡片同结构）
  - 6 项自检对备选也要跑通，不通过要在 alt 档注明 `partial_pass: true`
- 例外：当候选 > 10 条时可只对 Top 5 做全员微创新，其余只存档原版

## 十、v0.4 增量规则（验收问题驱动，2026-08-16）

> 来源：3 样本 × 4 维度 × 5 候选验收，60 个候选 80% 换皮
> 方法：按手册 §5.1「一次只改一条」迭代

### R2 修订 · 保留"钩子关键词"而非"钩子完整句"

**问题**：原文 R2"必须保留至少 1 个原 hook 关键词"被误读为"保留完整核心句"，导致样本 1 5 候选全部复用"我不为赚钱..."这句台词。

**修订**：
- MUST 保留**关键词**（如"30 年 / 凌晨 / 闭眼 / 老茧"等名词/数字），不保留完整句
- MUST NOT 5 候选里出现 ≥2 个相同的"完整核心句"
- 核心台词（如"我不为赚钱..."）在 5 候选中至多复用 1 次，其余 ≥3 种必须改写

**改写示例**：
- ❌ 保留："我不为赚钱，就是想让早起赶路的人有口热的。"
- ✅ 改写 1："赚钱？我二十年前就不为这个干了。"
- ✅ 改写 2："不为别的，就为早起赶路的人能端上一碗热的。"
- ✅ 改写 3："开这店不为别的，就图个有人来。"

### R15 · 结构差异化（5 候选 ≥3 种骨架）

**问题**：样本 1 5 候选全部是"XX 守了 30 年 + 凌晨 3 点 + 灶台 + 留口热的"同结构。

**规则**：
- 5 个候选的结构骨架至少 **3 种不同**
- 推荐结构骨架库（5 选 3）：
  1. **坚守**（默认）：时间跨度 + 重复动作 + 初心台词
  2. **传承**：老一辈 → 交棒 → 离开 → 回来探望
  3. **反悔 / 转折**：开头正常 → 中段动摇 → 末段决意
  4. **对照 / 闪回**：过去 vs 现在，画面交叉
  5. **被发现 / 旁观者**：路人发现 → 追溯 → 揭示真相

**自检**：5 候选的骨架标签必须 ≥3 种不同。

### R16 · 前 3 秒钩子（开头必须有数字 / 反差 / 悬念）

**问题**：5 候选开头全是"南方小镇上 / 草原深处 / 苗圃深处"慢热场景铺陈，0 钩子。

**规则**：
- 每个候选的前 30 字必须含以下任一钩子元素：
  - **数字**：具体数字（"30 年 / 1095 天 / 70 岁 / 凌晨 3 点"）
  - **反差**："本应 X，实际 Y" / "都以为 X，没想到 Y"
  - **悬念**：未完成的悬念 / 反问 / 省略号关键信息
- MUST NOT 前 30 字只是纯场景铺陈（"在 XX 地方 / 在 XX 时间 / XX 是个...的人"）

**反例**：
- ❌ "南方小镇上，一家开在巷口的早餐店。"
- ✅ "凌晨 3 点，30 年了，灯还亮着。"
- ✅ "本应早就关了，可她说：'再守一年。'"

### R17 · 长度约束（候选 ≤ 80 字）

**问题**：候选普遍 100-150 字，超出短视频 prompt 黄金长度（60-80 字）。

**规则**：
- 候选 MUST ≤ 80 字（含技术规格 9:16 / 4K / 60s）
- 超 80 字 MUST 自动标 `too_long: true` 并重写
- 重写策略：砍冗余镜头描写，只留核心场景 + 1 个动作 + 1 句台词 + 技术规格

### R18 · 逻辑自洽校验

**问题**：样本 3 候选"50 年没嫁的姐姐"逻辑漏洞（70-50=20 岁出门）。

**规则**：
- 候选 MUST 不含年龄差矛盾（如人物 A 70 岁，回溯 50 年 = 20 岁才合理）
- 候选 MUST 不含凭空添加的人物关系（原文未提的女儿已故不可硬加）
- 候选 MUST 时间线自洽（"30 年前"的人物关系要符合角色年龄）
- 校验不通过 MUST 标 `logic_flaw: true` 并触发 Profile §6.1 兜底 review

### R19 · 受众感知钩子词分层（按 Profile L5）

**问题**：钩子词统一用"致敬"（男性向/官方化），与 Profile L5"女性 60%+, 18-40 岁"不匹配。

**规则**：钩子词按受众画像分层：
| 受众 | 推荐钩子词 | 避免 |
|---|---|---|
| 女性向（≥60%） | 心疼 / 求求 / 帮忙 / 忍不住 / 看哭了 / 谁懂 | 致敬 / 加油 / 努力 |
| 男性向 | 致敬 / 支持 / 顶一个 / 干得漂亮 | 心疼 / 看哭了 |
| 通用 | 请点赞 / 麻烦帮我 / 谢谢 | （无禁忌） |

**自检**：5 候选的钩子词至少 **3 种不同**（R21）。

### R20 · 避雷清单硬规则（量化"空镜过多"）

**问题**：避雷清单"空镜过多（> 5 秒无台词）"全部候选照样过审。

**规则**：
- 候选中**镜头描写 > 30 字** 且 **无强事件/台词** → MUST 失败
- "强事件" 定义：含具体动作（不是"推进"而是"举起杯子"）+ 含可观察变化
- 反模式镜头词：`镜头从外推入 / 慢慢拉到 / 朦胧了灯光 / 蒸汽缭绕` 这些纯氛围词堆砌 → MUST 失败

**自检正则**：候选中 `镜头[\u4e00-\u9fa5]{30,}` 且不含动作动词 → 失败。

### R21 · 5 候选钩子词差异化（≥3 种）

**问题**：5 候选里"致敬"出现 3 次，"祝福"出现 2 次。

**规则**：5 候选末尾的钩子句（"请给...点赞..."部分）必须 **≥3 种不同的钩子词**。

**示例**（样本 1 改写后）：
- 候选 1："请给这对师徒点赞致敬"（致敬）
- 候选 2："求求大家帮帮这对父子"（求求）
- 候选 3："忍不住心疼这对老药农"（心疼）
- 候选 4："看哭了，请给守塔父子加油"（看哭了）
- 候选 5："麻烦帮我转给每一位支教老师"（麻烦帮我）

### R22 · 空 prompt 触发兜底（不硬塞补丁）

**问题**：样本 2 空 prompt（"几个朋友周末爬山聊天吃零食"）硬塞 5 个补丁候选，**没有真改写**。

**规则**：
- 候选 MUST 含至少 **1 个奠基动作**（如"领 / 收养 / 等待 / 退休 / 团圆 / 送别 / 重逢"）
- 奠基动作 = 0 → 触发 Profile §6.1 兜底 review，**不输出 5 候选**
- 兜底卡片内容：原 prompt + 提示"原 prompt 缺乏奠基动作，请补充人物关系/情感锚点后重试"

## 十一、回归验证清单（用 sample-1 重跑确认）
